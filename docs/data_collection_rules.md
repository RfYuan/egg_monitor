## 1. 数据采集总则

### 1.1 核心原则

| 原则 | 说明 |
|------|------|
| **真实性** | 所有数据必须来自真实数据源，禁止使用模拟/估算数据 |
| **可追溯性** | 每条数据必须记录来源、采集时间和采集方式 |
| **完整性** | 数据字段必须完整，缺失字段需明确标记为NULL |
| **时效性** | 数据采集必须在规定时间窗口内完成 |
| **容错性** | 单一数据源失效不应导致整个系统崩溃 |

### 1.2 数据采集流程图

```
数据源1 → 成功 → 验证数据 → 存储 → 完成
    ↓ 失败
数据源2 → 成功 → 验证数据 → 存储 → 完成
    ↓ 失败
数据源3 → 成功 → 验证数据 → 存储 → 完成
    ↓ 失败
发送告警 → 记录日志 → 返回失败
```

## 3. 数据有效性标准

### 3.1 数据格式验证

| 字段类型 | 验证规则 | 示例 |
|----------|----------|------|
| 日期 | YYYY-MM-DD 格式 | 2026-06-15 |
| 价格 | 正数，最多2位小数 | 4345.50 |
| 数量 | 非负整数 | 12500 |
| 比率 | 0-100范围，最多2位小数 | 52.35 |

### 3.2 数据范围验证

| 数据类型 | 合理范围 | 异常处理 |
|----------|----------|----------|
| 鸡蛋期货价格 | 3000-6000元/500kg | 超出范围触发告警 |
| 现货价格 | 6-12元/斤 | 超出范围触发告警 |
| 持仓量 | 0-500000手 | 负数或超大值拒绝 |
| 仓单数量 | 0-10000张 | 负数拒绝 |

## 4. 错误处理规则

### 4.1 重试规则

| 错误类型 | 重试次数 | 重试间隔 | 说明 |
|----------|----------|----------|------|
| 网络超时 | 3次 | 2秒 | 网络不稳定 |
| 服务端错误(5xx) | 2次 | 5秒 | 服务器临时故障 |
| 客户端错误(4xx) | 0次 | - | 无需重试 |
| 限流错误(429) | 1次 | 60秒 | 等待限流解除 |

### 4.2 失败处理流程

```
采集失败 → 记录详细日志 → 发送飞书告警 → 标记任务失败 → 等待下次执行
```

### 4.3 告警级别定义

| 级别 | 标识 | 触发条件 | 通知方式 |
|------|------|----------|----------|
| INFO | ℹ️ | 正常状态变更 | 日志记录 |
| WARNING | ⚠️ | 数据采集失败、接口降级 | 飞书通知 |
| ERROR | ❌ | 系统故障、数据异常 | 飞书通知 + 日志告警 |
| CRITICAL | 🚨 | 核心功能失效 | 飞书通知 + 紧急处理 |

## 5. 禁止使用模拟数据规则

### 5.1 核心规定

> **严禁使用任何形式的模拟数据、估算数据或假数据填充真实数据缺失！**

### 5.2 禁止行为清单

| 禁止行为 | 示例 | 违反后果 |
|----------|------|----------|
| 使用默认值填充 | 价格缺失时填入0 | 数据污染 |
| 使用估算值 | 根据持仓总量估算多空持仓 | 误导分析 |
| 使用历史数据 | 用昨日数据代替今日数据 | 数据过期 |
| 使用随机数据 | 生成随机数填充 | 完全错误 |

### 5.3 正确处理方式

当所有数据源均失败时，应：

1. **记录详细错误日志**，包含：
   - 失败时间
   - 尝试的数据源列表
   - 每个数据源的错误信息
   - 重试次数和结果

2. **发送告警通知**，包含：
   - 数据类型
   - 失败原因
   - 建议的人工处理步骤

3. **返回失败状态**，不写入任何数据到数据库

4. **保持数据完整性**，相关依赖模块应能处理缺失数据

## 6. 异常情况处理

### 6.1 数据缺失处理

```python
# 正确做法：返回None或空列表，调用方处理
def get_holding_data(contract_id):
    data = fetch_from_source1()
    if data:
        return data
    
    data = fetch_from_source2()
    if data:
        return data
    
    # 所有数据源失败，返回None
    log.error("所有数据源均失败")
    notify_warning("数据采集失败")
    return None

# 调用方处理
data = get_holding_data("JD2609")
if data:
    process_data(data)
else:
    handle_missing_data()  # 优雅处理缺失
```

### 6.2 数据冲突处理

当多个数据源返回不一致数据时：

| 场景 | 处理策略 |
|------|----------|
| 官方API vs 第三方 | 以官方API为准 |
| 第三方 vs 爬虫 | 交叉验证，取多数值 |
| 数据差异 > 阈值 | 触发人工复核 |

### 6.3 空数据处理

```python
# 正确做法：字段缺失时设为NULL，不使用默认值
holding_data = {
    "date": trade_date,
    "symbol": contract_id,
    "long_qty": int(long_qty) if long_qty else None,  # 正确
    "short_qty": short_qty or 0,  # 错误！掩盖真实情况
}
```

## 7. 日志记录规范

### 7.1 日志级别使用

| 级别 | 使用场景 | 示例 |
|------|----------|------|
| DEBUG | 详细调试信息 | 函数进入/退出、参数值 |
| INFO | 正常业务流程 | 任务开始/完成、数据统计 |
| WARNING | 潜在问题 | 接口降级、数据缺失 |
| ERROR | 错误情况 | API调用失败、数据写入失败 |
| CRITICAL | 严重错误 | 数据库连接失败、核心服务不可用 |

### 7.2 日志格式要求

每条日志必须包含：
- **时间戳**: ISO 8601 格式
- **模块名**: 产生日志的模块
- **函数名**: 产生日志的函数
- **消息内容**: 清晰描述事件

```
2026-06-15 16:30:00 | INFO     | futures_collector:fetch_latest_quote:47 - [CACHE MISS] jd2609 fetching latest from AKShare...
```

### 7.3 必须记录的事件

| 事件类型 | 记录内容 |
|----------|----------|
| 任务启动 | 任务名称、计划执行时间 |
| 数据源切换 | 从A切换到B的原因 |
| 数据采集成功 | 数据量、关键指标 |
| 数据采集失败 | 失败原因、重试次数 |
| 数据写入 | 写入记录数、表名 |
| 告警发送 | 告警级别、接收方 |

## 8. 数据存储规范

### 8.1 数据库表设计原则

| 原则 | 说明 |
|------|------|
| **非空约束** | 主键、时间戳等必填字段必须设置NOT NULL |
| **默认值** | 非必填字段默认值应为NULL，而非0或空字符串 |
| **索引** | 查询频繁的字段（日期、合约代码）必须建立索引 |
| **时间精度** | 日期使用DATE类型，时间使用DATETIME类型 |

### 8.2 数据备份规则

| 备份类型 | 频率 | 保留期限 | 存储位置 |
|----------|------|----------|----------|
| 每日日志 | 每日 | 30天 | `logs/` |
| 每周数据库 | 每周日 | 3个月 | `data/backup/` |
| 上传文件 | 每次 | 永久 | `data/uploads/` |
