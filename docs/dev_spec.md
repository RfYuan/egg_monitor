# 鸡蛋期货(JD2609)监测系统 - 开发规格说明书

> **文档目的**：供业务人员审核项目范围、数据源、预警逻辑与交付标准
> **版本**：v1.0 | **日期**：2026-06-08
> **目标合约**：JD2609（大连商品交易所鸡蛋期货）
> **交易策略**：中长期多头，目标价 6500，止损位 3750

---

## 一、项目定位

### 1.1 系统做什么

本系统是一个**自动化行情监测与预警平台**，围绕 JD2609 合约实现以下闭环：

```
数据采集 → 数据存储 → 指标计算 → 规则匹配 → 飞书推送
```

### 1.2 核心价值

| 能力 | 说明 |
|------|------|
| 自动采集 | 每日自动抓取期货行情、现货价格，无需人工盯盘 |
| 智能预警 | 价格触及止损/目标位、仓单异动等场景自动推送飞书消息 |
| 数据沉淀 | 所有历史数据存入 SQLite，支持后续复盘分析 |
| 低成本运行 | 全部使用免费数据源，部署在腾讯云，零额外费用 |

### 1.3 不做什么（明确边界）

- **不做**交易执行（不连接期货账户下单）
- **不做**实时高频Tick级监控（日级别即可满足策略需求）
- **不做**产业数据全自动爬取（存栏/鸡苗等核心产业数据仍需人工录入）
- **不做**公网API暴露（仅本地运行，保障安全）

### 1.4 数据质量红线（强制要求）

> **禁止出现误导用户的数据！**

| 规则 | 说明 | 违反后果 |
|------|------|----------|
| **禁止推送过期数据** | 当日数据获取失败时，必须发送数据异常警报，**严禁**推送昨天或更早的旧数据 | 收件人可能根据过期价格做出错误交易决策 |
| **数据日期严格验证** | 所有推送的数据必须验证日期是否为当天，过期数据一律拒绝推送 | 同上 |
| **产业数据过期检查** | 产业数据（存栏/鸡苗等）超过7天视为过期，必须显示警告而非旧数据 | 用户可能根据过期的产业数据做出错误的中长期判断 |
| **数据缺失必须报警** | 数据源异常时，必须发送红色危险级别的警报通知 | 用户无法及时发现数据异常 |
| **合约代码统一** | 所有规则配置和数据库存储使用统一的合约代码格式（如 JD2609） | 规则匹配失败导致预警失效 |

**数据新鲜度标准：**
| 数据类型 | 新鲜度要求 | 过期阈值 |
|----------|------------|----------|
| 期货行情 | 当日数据 | 超过1天 |
| 现货价格 | 当日数据 | 超过1天 |
| 仓单数据 | 当日数据 | 超过1天 |
| **产业数据** | **周度数据** | **超过7天** |

**异常处理流程：**
```
数据获取失败 → 记录错误日志（CRITICAL级别）
            → 发送数据异常警报（danger级别，红色卡片）
            → 推送内容明确标注"数据获取失败"
            → 禁止发送任何可能被误解为有效数据的信息

产业数据过期 → 记录警告日志（WARNING级别）
            → 推送内容明确标注"数据已过期（超过7天），请人工录入最新数据"
            → 禁止显示过期的产业数据
```

## 二、数据源体系

### 2.1 数据源总览

系统接入 **4 类数据源**，按自动化程度分为「全自动」「半自动」「人工」三级：

```
┌─────────────────────────────────────────────────────┐
│                   数据源分层                          │
├──────────┬──────────┬───────────┬────────────────────┤
│ 全自动   │ 半自动   │  人工录入  │                    │
│ (API)    │ (爬虫)   │ (CSV上传) │                    │
├──────────┼──────────┼───────────┤                    │
│ AKShare  │ 生意社   │ 我的农产品网│                    │
│ 期货行情 │ 现货价格 │ 卓创周报     │                    │
│          │          │ 农业农村部   │                    │
└──────────┴──────────┴───────────┴────────────────────┘
```

### 2.2 全自动数据源（已实现）

#### ① AKShare — 期货行情（主力数据源）

| 项目 | 详情 |
|------|------|
| 获取内容 | JD2609 日K线：开盘价、最高价、最低价、收盘价、成交量、持仓量 |
| 更新频率 | 每个交易日盘后 |
| 成本 | 完全免费，无需注册 |
| 可靠性 | 高（开源社区维护，国内期货数据覆盖全） |
| 备选方案 | TqSdk（需注册账号，数据更实时） |

#### ② 生意社爬虫 — 现货价格（已预留接口）

| 项目 | 详情 |
|------|------|
| 获取内容 | 山东鸡蛋现货价、玉米现货价、豆粕现货价 |
| 更新频率 | 每日 10:00 |
| 技术方案 | requests + BeautifulSoup 定向抓取 |
| 合规性 | 低频请求（每日1次），符合网站使用规范 |

## 三、数据架构

### 3.1 存储方案

| 项目 | 选型 | 理由 |
|------|------|------|
| 数据库 | **SQLite** | 零运维、文件级备份、个人项目足够 |
| ORM框架 | SQLAlchemy | Python 标准 ORM，便于后续升级 MySQL |
| 备份策略 | 每周日自动备份数据库文件到 `data/backup/` |

### 3.2 数据表设计（6张核心表）

#### 表1：期货行情 (`futures_quote`)
— 存储每日 K线数据，支撑价格趋势分析和止损/目标位判断

| 字段 | 类型 | 说明 |
|------|------|------|
| symbol | 合约代码 | 如 JD2609 |
| datetime | 时间 | 数据时间点 |
| open/high/low/close | OHLC | 开高低收 |
| volume | 成交量 | 日成交量 |
| open_interest | 持仓量 | 日持仓量 |

#### 表2：仓单数据 (`futures_receipt`)
— 存储鸡蛋仓单日报，判断库存压力

| 字段 | 类型 | 说明 |
|------|------|------|
| date | 日期 |  |
| symbol | 品种 | jd |
| receipt_qty | 仓单数量 | 当日总量 |
| change | 增减量 | 较昨日变化 |

#### 表3：现货价格 (`spot_price`)
— 存储鸡蛋/玉米/豆粕现货报价，计算养殖成本和基差

| 字段 | 类型 | 说明 |
|------|------|------|
| date | 日期 |  |
| category | 品种 | egg / corn / soymeal |
| region | 地区 | 山东/全国等 |
| price | 价格 |  |
| unit | 单位 | 元/500kg 或 元/吨 |

#### 表4：产业数据 (`industrial_inventory`)
— 存储人工录入的存栏/鸡苗等周度数据

| 字段 | 类型 | 说明 |
|------|------|------|
| date | 日期 |  |
| inventory | 存栏量 | 万羽 |
| mom | 环比% | 较上周 |
| yoy | 同比% | 较去年 |
| source | 来源 | 卓创/农业农村部等 |

#### 表5：预警记录 (`alert_record`)
— 存储所有触发的预警，完整审计追踪

| 字段 | 类型 | 说明 |
|------|------|------|
| level | 等级 | info / warning / danger |
| title/content | 预警内容 |  |
| rule_id | 规则ID | 关联哪条规则触发 |
| data_snapshot | 数据快照 | 触发时的原始数据 |
| status | 状态 | pending(待处理) / resolved(已处理) |

#### 表6：系统日志 (`system_log`)
— 运行日志，排查问题用

## 四、预警体系

### 4.1 预警分级

| 等级 | 颜色 | 含义 | 推送方式 |
|------|------|------|----------|
| **danger** | 红色 | 危险 — 需立即行动（如跌破止损位） | 飞书卡片 + 数据库记录 |
| **warning** | 橙色 | 警告 — 需关注（如仓单大增） | 飞书卡片 + 数据库记录 |
| **info** | 蓝色 | 提示 — 信息通知（如接近目标位） | 飞书卡片 + 数据库记录 |

### 4.2 每日交易数据推送（新增）

除预警推送外，系统每日定时推送**交易数据汇总**，帮助用户快速了解当日市场状况：

| 项目 | 内容 |
|------|------|
| 推送时间 | 每个交易日 **16:00**（盘后数据更新完成后） |
| 推送等级 | info（蓝色卡片） |
| 推送内容 | 期货收盘价、涨跌幅、持仓变化；现货价格；仓单数据（如有） |
| 推送格式 | 飞书卡片消息，包含关键数据表格 |

#### 推送内容示例

```
📊 JD2609 每日数据汇总 (2026-06-08)

期货收盘：4345 (+2.3%)  持仓：12.5万手 (+5000)
现货价格：山东鸡蛋 4200元/500kg
仓单数据：今日无更新

基差：-145 (现货-期货)
```

> **说明**：每日数据推送与预警推送独立，无论是否触发预警都会发送，便于用户每日复盘。

### 4.3 已配置的预警规则（V1）

以下规则在 `config/alert_rules.yaml` 中定义，可随时调整：

#### 规则①：价格止损预警（danger）

| 项目 | 内容 |
|------|------|
| 触发条件 | JD2609 收盘价 < 3750 |
| 推送消息 | "JD2609价格已跌破止损位3750，建议立即平仓！" |
| 对应策略 | plan.md 模块1：有效跌破3750 → 全平多头 |
| 检查频率 | 每次期货行情采集后（交易日 9:30 / 15:40） |

#### 规则②：目标价位提示（info）

| 项目 | 内容 |
|------|------|
| 触发条件 | JD2609 收盘价 > 6300（距目标6500仅200点） |
| 推送消息 | "JD2609价格已接近目标位6500" |
| 对应策略 | plan.md 模块1：关注止盈时机 |
| 检查频率 | 同上 |

#### 规则③：仓单激增预警（warning）

| 项目 | 内容 |
|------|------|
| 触发条件 | 鸡蛋仓单单日增幅 > 20% |
| 推送消息 | "鸡蛋仓单大幅增加，注意库存风险" |
| 对应策略 | plan.md 模块1：仓单环比+20%，一级预警减仓50% |
| 检查频率 | 每日仓单数据更新后 |

#### 规则④：存栏连增预警（warning）

| 项目 | 内容 |
|------|------|
| 触发条件 | 在产蛋鸡存栏连续 2 周环比上升 |
| 推送消息 | "在产蛋鸡存栏连续上升，供应增加风险" |
| 对应策略 | plan.md 模块3：存栏连增2周 → 一级预警，减仓50% |
| 检查频率 | 每次产业数据录入后 |

### 4.3 预警扩展能力

新增预警规则只需编辑 `config/alert_rules.yaml`，无需改代码。支持的规则类型：

| 条件类型 | 用途示例 |
|----------|----------|
| `price_below` | 价格低于某阈值（止损） |
| `price_above` | 价格高于某阈值（目标/止盈） |
| `receipt_increase` | 仓单增幅超阈值 |
| `inventory_rise` | 存栏连续N周上升 |
| （可扩展） | 现货基差异常、成交量突变等 |

### 4.4 预警处理流程

```
规则触发 → 写入数据库(alert_record, status=pending)
         → 飞书群推送卡片消息
         → 人工查看飞书消息
         → 执行交易决策
         → (可选) 在系统中标记为已解决(resolved)
```

## 五、运行机制

### 5.1 定时任务调度

| 任务 | 执行时间 | 说明 |
|------|----------|------|
| 期货行情采集 + 预警检查 | 交易日 **09:30** | 盘前数据 |
| 期货行情采集 + 预警检查 | 交易日 **15:40** | 盘后数据 |
| **每日数据推送** | **交易日 16:00** | **推送当日交易数据汇总** |
| 现货价格采集 | 每日 **10:00** | 现货/饲料价格 |
| 数据库备份 | 每周日 **02:00** | 自动备份 |

> 使用 APScheduler 实现，程序启动后常驻内存等待定时触发。

### 5.2 启动方式

```bash
# 1. 创建虚拟环境
python -m venv venv
venv\Scripts\activate      # Windows
source venv/bin/activate   # Linux

# 2. 安装依赖
pip install -r requirements.txt

# 3. 配置 .env（填写飞书Webhook地址）
cp .env.example .env
# 编辑 .env，填入 FEISHU_WEBHOOK_URL

# 4. 运行
python src/main.py
```

### 5.3 部署环境

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux（腾讯云 CentOS/Ubuntu） |
| Python | 3.10+ |
| 网络 | 能访问外网（调用 AKShare/飞书 API） |
| 安全 | 不暴露公网端口，仅本地运行 |
