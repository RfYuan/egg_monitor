# 鸡蛋期货(JD2609)监测系统 - 数据源计划
## 一、计划概述
### 1.1 核心目标
围绕 JD2609 合约的「自动化行情监测 + 产业数据支撑」核心需求，分阶段落地**4 类免费数据源**的对接，优先保障全自动数据源稳定运行，逐步补齐半自动 / 人工数据源，最终实现「行情 + 现货 + 产业 + 风险」的全维度数据支撑。
### 1.2 分期原则
- 优先级：官方API（核心）> 全自动爬虫 > 半自动爬虫 > 人工录入体系 > 黑天鹅监测 > 备用数据源
- 合规性：所有爬虫类操作遵循「低频、定向、非商用」原则，避免反爬 / 合规风险
- 可落地性：第一阶段优先用「官方免费 + 低开发成本」方案，后续逐步迭代优化

## 三、各数据源核心要求
### 3.1 数据采集频率 & 时间要求
| 数据源 | 采集频率 | 执行时间 | 容错机制 |
|--------|----------|----------|----------|
| AKShare 期货行情 | 每个交易日 2 次 | 09:30（盘前）、15:40（盘后） | 采集失败重试 3 次，间隔 5 分钟 |
| **养殖网现货价格** | **每日 1 次** | **10:00** | **养殖网失败则切换至备用数据源（农业农村部）** |
| 农业农村部现货价格 | 每日 1 次（备用） | 10:00 | 当日失败则次日补采 |
| **大商所仓单数据** | **每日 1 次** | **16:30（大商所更新后）** | **API失败重试2次，仍失败则切换至AKShare** |
| **大商所前20持仓** | **每周 1 次** | **周五17:00** | **API失败触发飞书告警，人工补录** |
| **大商所公告** | **每日 1 次** | **09:00** | **无重试，失败则当日人工检查** |
| 产业数据（CSV 上传） | 每周 1 次 | 每周一 09:00 前（人工上传） | 支持补传上周数据 |
| 黑天鹅监测 | 每日 1 次 | 09:00 | 无容错，漏采仅当日人工巡检补充 |

#### 现货价格数据源优先级

| 优先级 | 数据源 | 可靠性 | 数据覆盖 | 备注 |
|--------|--------|--------|----------|------|
| **1（主数据源）** | **养殖网** | **高** | **全国各省市** | **每日更新，数据最全面** |
| 2（备用） | 农业农村部 | 中 | 全国均价 | 官方数据，但更新较慢 |

**数据采集策略：**
```
job_collect_spot():
    1. 尝试养殖网爬虫采集
    2. 成功 → 写入数据库，结束
    3. 失败 → 切换至农业农村部备用数据源
```

### 3.2 大商所API使用规范
1. **调用频率限制**：严格遵守大商所API每分钟不超过60次的限制，所有接口调用间隔≥1秒；
2. **密钥管理**：API Secret存储在 `.env` 环境变量中，禁止硬编码到代码或提交至Git；
3. **数据一致性**：以大商所API返回数据为准，与AKShare数据存在差异时优先使用官方数据；
4. **错误处理**：所有API调用添加异常捕获，返回非200状态码时记录详细日志并触发告警。

### 3.3 合规性保障
1. 爬虫类操作：所有网站爬取均限制「单 IP 每日≤1 次」，设置标准浏览器请求头（User-Agent），不爬取非公开数据；
2. 数据使用：仅用于内部个人监测分析，不对外分发、商用或二次加工售卖；
3. 备用方案：核心数据源（如期货行情、现货价格）均预留官方免费备选方案，避免单一数据源失效导致系统瘫痪。

### 3.4 数据存储 & 备份要求
1. 存储：所有数据严格按照数据表设计存入 SQLite，字段格式、单位与开发文档定义完全对齐；
2. 备份：
   - 每日：程序运行日志自动备份至 `logs/` 目录，保留 30 天；
   - 每周：周日 02:00 自动备份 SQLite 数据库文件至 `data/backup/`，保留近 3 个月备份；
   - 人工：产业数据 CSV 上传后自动备份至 `data/uploads/backup/`，永久保留原始文件。
